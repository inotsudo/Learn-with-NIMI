# NIMIPIKO store apps (Google Play + App Store)

The Android and iOS apps are the NIMIPIKO web app wrapped with **Capacitor 8**. There is one codebase; the native projects live in `android/` and `ios/`.

| | |
|---|---|
| App name | **NIMIPIKO** |
| App ID (both stores, permanent) | **com.nimipiko.app** |
| Android | min Android 7.0 (API 24), targets Android 16 (API 36) |
| iOS | Swift Package Manager project (no CocoaPods) |
| Config | `capacitor.config.ts` |
| Bundled web folder | `mobile/www` (launch + offline screens) |
| Icon / splash sources | `mobile/assets` (regenerate: `npm run mobile:art`, then `npm run mobile:assets -- --android --ios`) |
| Launch / offline screens | generated by `npm run mobile:shell` (self-contained HTML; Capacitor serves only that one file when offline) |

## How the app finds NIMIPIKO

`CAP_SERVER_URL` decides which NIMIPIKO the app opens. It is read by `npx cap sync`:

| Where | Command |
|---|---|
| Android emulator → this computer's dev server | `CAP_SERVER_URL=http://10.0.2.2:3000/home npx cap sync android` |
| Phone on the same Wi-Fi | `CAP_SERVER_URL=http://<LAN-IP>:3000/home npx cap sync android` (add the IP to `allowedDevOrigins` in `next.config.mjs`) |
| Release builds | the production app URL. **Not decided yet**: the live site stays on the old version until the redesign is finished. |

The app opens the children's world at `/home` (it redirects to sign-in when needed), so give the full URL, e.g. `http://10.0.2.2:3000/home`. Without `CAP_SERVER_URL`, the app shows the bundled launch screen. If the network is down, the app shows `mobile/www/offline.html`.

## Android on this computer

The tools live in your home folder, so no admin rights are needed:
- JDK 21: `~/Android/jdk-21`
- Android SDK: `~/Android/Sdk` (platform 36, build-tools 36, emulator, Android 16 system image)

Each terminal needs this environment first:

```bash
export JAVA_HOME=$HOME/Android/jdk-21 ANDROID_HOME=$HOME/Android/Sdk
export PATH=$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH
```

```bash
npm run dev                                              # web dev server on :3000
CAP_SERVER_URL=http://10.0.2.2:3000/home npx cap sync android
(cd android && ./gradlew assembleDebug)                  # → android/app/build/outputs/apk/debug/app-debug.apk
emulator -avd nimipiko_phone &                           # or nimipiko_tablet
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.nimipiko.app/.MainActivity
```

Emulators:
- `nimipiko_phone` (Pixel 7)
- `nimipiko_tablet` (Pixel Tablet)

## iOS

iOS apps can only be built on macOS. This computer runs Linux, so iOS builds will run on a **cloud Mac service** (Codemagic or GitHub Actions macOS runners) from the GitHub repository. Setting this up needs the Apple Developer account.

## Before submitting to the stores

**Accounts (not created yet):**
- Apple Developer Program ($99/year)
- Google Play Console ($25 once)

**Release URL:** pick how release builds load the app:
- (a) the deployed production site via `CAP_SERVER_URL`; or
- (b) a bundled build of the web app.

Apple may reject apps that only wrap a website, so the native features below must be in place:

1. **Payments:**
   - Inside the apps, use **Apple In-App Purchase / Google Play Billing** for subscriptions.
   - Card and MoMo stay on the website only.
   - The apps must not link out to the website to buy.
2. **Kids category rules** (Apple Kids, Google Families):
   - a parental gate before purchases, external links and settings;
   - no third-party ads or advertising/tracking SDKs;
   - a privacy policy that covers children's data;
   - children's photos stay private (see `docs/brand/official/README.md` §6).
3. **Sign in with Google:** Google blocks OAuth inside an embedded web view, so the apps need a native sign-in plugin or the system browser.
4. **Native polish:** push notifications (FCM/APNs), the offline screen, haptics, and a correct back button on Android.
5. **Store listings:**
   - screenshots for phone and tablet in both orientations;
   - an age rating questionnaire;
   - the content descriptions in French, English and Kinyarwanda.
